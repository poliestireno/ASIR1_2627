# RA12_NCA_WEB_PODCAST

## ENUNCIADO

Web anunciando tu podcast y que se pueda reproducir vía web el audio.

- Mínimo una página por persona del equipo.
- Utilizar bootstrap principalmente y si necesitáis un mínimo retoque de css.
- La web estará toda en inglés.
- Se expondrá el día siguiente a la entrega.
- La web servirá de "diapositivas" para la exposición.

Se puede utilizar la plantilla bootstrap siguiente:
https://www.w3schools.com/bootstrap5/bootstrap_templates.php

### Ideas para las páginas

- Anuncio del podcast como si fuera un cartel.
- Página donde está en enlace para escucharlo y resumen.
- Página con los créditos y las personas que habéis participado y con qué roles.
- Página de mejores momentos y anécdotas.
- Página donde se explica a nivel técnico vuestro.
- Página de lo que creáis que cuadre con vuestro podcast y con vosotros (CREATIVIDAD).

### Entrega

- La web completa se entregará subida al repositorio de GitHub público y también al repositorio privado.
- Todos los integrantes del equipo tienen que subir la web completa a sus repositorios (no solo su página).

**FIN ENUNCIADO**

## DESAFÍO NCA

**Desafío Nº:** `RA12_NCA_WEB_PODCAST`

# On air: la web de vuestro podcast, en inglés y lista para exponer

Crear en equipo, con Bootstrap, una web en inglés que anuncie vuestro podcast, permita escucharlo desde el navegador y sirva de soporte visual para presentarlo en clase.

### Objetivos técnicos

- Construir un sitio web multipágina, con al menos una página por integrante del equipo, enlazadas mediante una barra de navegación común.
- Maquetar las páginas principalmente con Bootstrap 5 (rejilla, componentes y utilidades), partiendo opcionalmente de una plantilla, con solo retoques mínimos de CSS propio.
- Integrar el audio del podcast para que se pueda reproducir directamente en la web (`<audio>` con controles o reproductor incrustado).
- Redactar todo el contenido de la web en inglés.
- Publicar la web completa en el repositorio de GitHub público y en el privado de cada integrante del equipo.
- Diseñar las páginas para que funcionen como "diapositivas" de la exposición oral: cartel, resumen, créditos, mejores momentos, aspectos técnicos y una página creativa propia.

### Módulos implicados

- CFGS Administración de Sistemas Informáticos en Red – ASIR, módulo Lenguajes de Marcas (MAR)
- CFGS Administración de Sistemas Informáticos en Red – ASIR, módulo Inglés I

### Resultados de aprendizaje

- **RA1.** Reconoce las características de lenguajes de marcas analizando e interpretando fragmentos de código.
- **RA2.** Utiliza lenguajes de marcas para la transmisión de información a través de la Web analizando la estructura de los documentos e identificando sus elementos.

### Elementos transversales / competencias

Trabajo en equipo, comunicación oral, inglés, creatividad, competencia digital

### Principios pedagógicos

### Sesiones

Acogida 1 · Explorar 1 · Idear 1 · Materializar 3 · Cierre 1 — **Total: 7 sesiones en 7 días**

### Fases

**Acogida** — 1 sesión
- Presentación del desafío: dar visibilidad al podcast del equipo con una web propia, en inglés, que además será el soporte de la exposición del día siguiente a la entrega.

Observación: se presenta la web como un producto real de promoción del podcast, no como un ejercicio aislado de HTML.

**Explorar** — 1 sesión
- Conocer Bootstrap 5: cómo incluirlo, sistema de rejilla (`container`, `row`, `col`), y componentes útiles para el reto (navbar, cards, carousel, jumbotron/hero, botones) — pond. 2
- Revisar las plantillas de Bootstrap de W3Schools y cómo adaptar una a un sitio propio — pond. 1
- Ver cómo incrustar audio en una página web (`<audio controls>`, formatos admitidos, o reproductor incrustado de una plataforma externa) — pond. 1
- Repasar cómo compartir el código del equipo con Git y GitHub para que todos tengan la web completa y puedan subirla a su repositorio público y a su privado — pond. 1

Observación: se dan los anclajes justos para maquetar con Bootstrap sin depender del CSS propio.

**Idear** — 1 sesión
- Decidir en equipo qué páginas tendrá la web (al menos una por integrante) a partir de las ideas del enunciado, y repartir quién se encarga de cada una — pond. 2
- Bocetar la estructura de navegación y la idea visual común (plantilla, colores, tipografía, estilo del cartel) para que el sitio sea coherente — pond. 1
- Acordar cómo se va a juntar el trabajo de todos en una única web y cómo la tendrá completa cada integrante — pond. 1
- Pensar la página creativa propia: qué encaja con vuestro podcast y con vosotros — pond. 1

Observación: se planifica el sitio pensando también en cómo se va a usar como "diapositivas" durante la exposición.

**Materializar** — 3 sesiones
- Montar la estructura común del sitio con Bootstrap: plantilla base, barra de navegación y enlaces entre todas las páginas — pond. 2
- Crear la página de cartel y la página de escucha con el resumen y el audio reproducible en la web — pond. 3
- Crear el resto de páginas (créditos y roles, mejores momentos y anécdotas, explicación técnica y página creativa), cada integrante la suya — pond. 3
- Redactar y revisar todos los textos en inglés, y aplicar solo los retoques mínimos de CSS necesarios — pond. 2
- Juntar todas las páginas en la web final y que cada integrante suba la web completa a su repositorio de GitHub público y a su repositorio privado — pond. 2

Observación: es la fase central — se evalúa que la web funcione, que el audio se reproduzca, que esté en inglés, que cada integrante haya aportado su página y que todos tengan la web completa en sus dos repositorios.

**Cierre** — 1 sesión
- Exposición de cada equipo, el día siguiente a la entrega, usando su propia web como diapositivas y presentando cada integrante su página.

Observación: la web demuestra su utilidad como soporte de comunicación al presentar el podcast ante el resto de la clase.
